### 4. 优化任务复杂度分级
**位置**：编码前上下文收集 → 任务复杂度分级

**改动前**：
- 简单任务（单文件、<50行）：执行步骤 1-3
- 中等任务（多文件、<200行）：执行步骤 1-5
- 复杂任务（架构级、>200行）：执行全部 7 步骤

**改动后**：
新增**判断标准表格**：

| 复杂度 | 代码量 | 涉及文件 | 架构影响 | 检索步骤 |
|--------|--------|----------|----------|----------|
| 简单 | <50行 | 1-2个文件 | 无架构变更，局部修改 | 1-3 |
| 中等 | 50-200行 | 3-5个文件 | 可能影响多个组件 | 1-5 |
| 复杂 | >200行 | >5个文件 | 涉及架构设计或核心模块 | 全部7步 |

新增**具体示例**：
- 简单任务：修改按钮样式、调整文案、简单的 Bug 修复
- 中等任务：新增一个 UI 组件、扩展现有功能、重构单个模块
- 复杂任务：新增布局算法、重构状态管理、实现国际化系统

**价值**：提供更清晰的判断标准，帮助准确评估任务复杂度。

### 5. 新增错误处理规范章节
**位置**：代码质量标准 → 性能意识之后

**包含内容**：
- **用户输入验证**：对所有用户输入进行边界检查
- **异步操作处理**：使用 try-catch 包裹异步代码
- **错误提示**：提供清晰的错误信息（使用 i18n 国际化）
- **降级策略**：关键功能失败时提供替代方案
- **日志记录**：使用 console.error 记录错误详情（开发环境）

**代码示例**：
```typescript

  await processImage(file)
} catch (error) {
  console.error('图片处理失败:', error)
  showToast(t('errors.imageProcessFailed'), 'error')
  // 提供降级方案或引导用户操作
}
```

**价值**：规范错误处理模式，提升应用的健壮性和用户体验。
